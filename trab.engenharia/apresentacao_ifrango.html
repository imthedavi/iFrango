O Desafio e a Proposta

🎯

O Problema

Sistemas de delivery comuns operam para um único lojista (Single-tenant). O desafio foi projetar uma arquitetura onde múltiplos restaurantes coexistissem na mesma base de dados, sem vazamento de informações.

🔄

A Solução (MVP)

Um módulo web responsivo integrado a um banco de dados relacional. Permite a gestão descentralizada do cardápio pelos fornecedores e um fluxo de checkout assíncrono para os clientes.

Stack Tecnológica

🐳

Docker

Orquestração e isolamento de contêineres para garantir portabilidade entre desenvolvimento e produção.

⚡

FastAPI (Python)

Back-end de alta performance com tipagem estrita, documentação automática e rotas RESTful blindadas.

🐘

PostgreSQL

Persistência relacional sólida. Integridade garantida via ORM SQLAlchemy (Chaves Estrangeiras estritas).

🎨

Vanilla JS / Tailwind

Single Page Application (SPA) assíncrona, focada em UX rápida sem recarregamento de página.

Refatoração e Code Smells

Durante o ciclo de desenvolvimento iterativo (XP/Scrum), identificámos e corrigimos gargalos críticos:

  • 🛡️
    Segurança de Autenticação Mapeamento inicial usava GET na URL para login. Refatorado para POST /usuarios/login garantindo payload seguro.
  • 🔑
    Integridade Referencial (MER) A tabela pedidos foi refatorada para exigir usuario_id e restaurante_id, resolvendo o problema de dados misturados.
  • *
    Polimento de UX Substituição de alert() nativos por notificações Toast assíncronas e persistência de sessão via LocalStorage.
